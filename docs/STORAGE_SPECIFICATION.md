# Storage Engine Specification — Komüte-Local

> **Specifications for session persistence, raw specimen capture, privacy-isolated crop extraction, and post-verification WebP compression.**

---

## 1. Overview & Architectural Role

The `storage/` folder provides an isolated, portable persistence layer for verification sessions. It records physical specimens, extracted crops, and audit metadata during onboarding runs.

### Architectural Decoupling Guarantee
* **Zero Backend Dependency**: Core machine learning inference and verification logic run independently of the `storage/` folder.
* **Safe Deletion**: Deleting the `storage/` folder or any nested subfolders at any time has **zero effect** on backend neural model execution, barcode decoding, or API verification contracts.

---

## 2. Directory Hierarchy & Nested Structure

When an onboarding verification request is processed, the storage engine organizes artifacts under a clean, sandboxed path:

## 3. Storage Sub-Folder Roles & Contracts

### 3.1 `originals/` — Raw Ingested Specimens
Preserves exact, uncompressed camera uploads as received from the client for forensic auditability:
* **`selfie_original.jpg`**: Raw smartphone live portrait capture.
* **`license_original.jpg`**: Raw driving license card front photo.
* **`license_back_original.jpg`**: Raw driving license card back photo with AAMVA PDF417 barcode.
* **`vehicle_original.jpg`**: Raw vehicle exterior photo with visible license plate.

### 3.2 `cropped/` — Privacy-Isolated Crops
Stores localized, sanitized image crops generated by detection algorithms during pipeline execution:
* **`selfie_face_crop.webp`**: Face isolated by YuNet, deskewed via 5-point Umeyama canonical affine alignment ($112 \times 112$).
* **`dl_face_crop_sanitized.webp`**: Facial portrait isolated from the driver's license card. Card template text, address lines, and license numbers are 100% excluded (Zero-PII compliance).
* **`vehicle_plate_crop.webp`**: Tight bounding box crop of the vehicle license plate isolated by YOLOv9-Tiny.

### 3.3 `compressed/` — Post-Verification Normalized WebP Assets
Following successful verification, images are saved as normalized, bandwidth-efficient WebP assets for long-term cloud archival:
* **Format**: WebP (`.webp`) format utilizing standard quality profiles.
* **Quality Targets**:
  * Live Selfie Portrait: Quality 80
  * License Card Front: Quality 70
  * License Card Back: Quality 70
  * Vehicle Exterior: Quality 85

## 5. Security & Sanitization Policies

* **Path Traversal Protection**: All folder names (`driver_id`, `request_id`, `preview_id`) pass through `sanitize_folder_name()`, strictly removing forward slashes, backslashes, consecutive periods (`..`), and non-alphanumeric characters.
* **Local Sandboxing**: All writes are bound to the configured `uploads/` directory with automatic recursive directory creation.
